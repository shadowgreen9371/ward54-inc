# Ward 54 INC — 7-Layer Security Architecture

This document describes the defense-in-depth layers protecting the
public site (kolkata54ward.in), the admin panel, the Firebase
Realtime Database, and the GitHub repository.

The goal: **even if one layer is bypassed, the others still block
the attacker.**

```
INTERNET ▶ Domain ▶ Browser ▶ GitHub ▶ Firebase Auth ▶ Firebase DB ▶ API Key ▶ App
          Layer1   Layer2    Layer3   Layer4         Layer5         Layer6     Layer7
```

## LAYER 2 — Browser-side security headers

Embedded as `<meta>` tags in `index.html` and `admin.html`. GitHub
Pages can't set true HTTP response headers (no edge config), so we
use the `<meta http-equiv="…">` equivalents — browsers honour them.

| Header | Effect |
|---|---|
| `Content-Security-Policy` | Locks down which hosts can serve JS, CSS, images, fonts, frames, fetch targets. Blocks XSS, malicious CDN injection, untrusted iframes. |
| `X-Frame-Options: SAMEORIGIN` (public), `DENY` (admin) | Prevents clickjacking. |
| `Referrer-Policy: strict-origin-when-cross-origin` | Doesn't leak visited page path to third parties. |
| `Permissions-Policy` | Disables camera/mic/geo/payment/USB except where needed. |

## LAYER 5 — Firebase Realtime Database rules

Initial rules locked `/cms` to admin allowlist. **Upgrade to
`firebase-rules-v2.json`** (this commit) for hardened version:

- `/cms` — public read, write requires authenticated admin allowlist
- `/audit_log` — admin-only read/write, append-only (writes denied if key exists), shape + size validation
- `/chat` — public read/write, validated shape (text + who + t), 2 KB max per message, immutable once written
- Everything else — denied by default

To apply: paste `firebase-rules-v2.json` contents into Firebase
Console → Realtime Database → Rules → Publish.

## Incident response

If you suspect compromise:

1. Revoke all GitHub PATs (github.com/settings/tokens)
2. Reset Firebase Auth admin passwords (Firebase Console → Authentication → Users → tap email → "Reset password")
3. Restore from nightly backup: `git log --all -- data/cms/cms-backup.json` shows snapshots; paste the relevant version back into Firebase Console → Realtime Database → import JSON
4. Rotate Firebase API key (Google Cloud Console → Credentials → "Regenerate key") and update `FIREBASE_CONFIG` in `index.html` and `admin.html`
5. Force re-login of all active sessions (Firebase Console → Authentication → Users → "Sign out user")
